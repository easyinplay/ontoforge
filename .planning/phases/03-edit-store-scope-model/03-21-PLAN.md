## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

> 来源说明见 03-01-PLAN.md 的 Phase Goal 节（ROADMAP 的 Goal 行不是 user story 格式，本节沿用 03-01 由 Goal 原文组成的版本，未新编）。

<objective>
Gap closure 1（03-VERIFICATION.md gaps[0]，审查 CR-A01），并入同一校验边界上的 WR-A01 与 WR-A03。

客户端送来的值必须原样落进强类型 edit 行、不可变 edit log 与历史快照。现在有两处会悄悄改值或在校验之后才失败：

1. decimal 的 JSON 数字先被 serde_json 解析成 f64，`value.rs` 第 326 行再打印成最短往返文本，17 位以上有效数字被舍入后通过校验，写进只能追加的日志。
2. `PropertyValue::canonical` 接受 PostgreSQL 存不下的值：U+0000、年份 0000、经偏移换算落到 0000 年的 timestamp。SQLite 照存，PostgreSQL 在写入时以不透明的 `StoreError` 失败，这也破坏 import「先查完整个文件再写」的承诺。

另外，PostgreSQL 的 date 与浮点文本读取依赖会话设置。读 sqlx-postgres 0.9.0 源码得知：`connection/establish.rs` 第 25-38 行每个连接的启动包都带 `DateStyle = "ISO, MDY"`、`TimeZone = "UTC"`，并带 `options/mod.rs` 第 97 行缺省的 `extra_float_digits = "2"`。客户端启动参数优先于 `ALTER ROLE` / `ALTER DATABASE` 设置，所以据源码判断，审查描述的失败在锁定的依赖版本下不会发生（未实测）。本 plan 仍把这些设置显式固定在 `search_path` 旁，并用守卫测试直接断言会话上的取值，使它不再隐式依赖 sqlx 的缺省值（WR-A03 足够小，按 orchestrator 指示并入；不并入的条件不成立）。

Purpose: 让 SC1「强类型」、SC2「不可变 log」与 STORE-03 / STORE-06 的「记录的就是提交的」成立。WR-A01 让两个后端对「什么值合法」的判断一致，属于 STORE-01 的同一套 conformance。D-10 / D-11 规定 log 存提交的新值，本 plan 保证存进去的就是客户端送来的值。
Output: `value.rs` / `commit.rs` / `store.rs` 的校验与连接修正；import、conformance（两后端）与 PG 守卫测试；`docs/edit-store.md` 的 import 取值说明。

不做（orchestrator 明确排除）：不打开工作区级的 serde_json 任意精度 feature（全工作区 serde 变更，超出范围）；不处理审查的 CR-B01、CR-D02 与其余 warning。
</objective>
