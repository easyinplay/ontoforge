## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

> 来源说明见 03-01-PLAN.md 的 Phase Goal 节。

<objective>
roles-as-code 的管理通道：管理员把 scope 目录同步进系统库，每次变更都可预览、可审计、全量同步。tracer 打通「scope 目录 → 离线编译 → plan → apply → 系统库 + 审计」，再补齐全量同步的删除、hash 防漂移、索引对账、user 记录与源码守卫。

Purpose: SCOPE-01（管理用户 / 组 / 角色，角色绑定到 user / group）、SCOPE-07（只经管理通道修改并审计）、SCOPE-02（存储层的规范化与排序）、SCOPE-06（apply 侧的 criteria 覆盖检查经 03-12 生效）；实现 D-01、D-02、D-03、D-04。
Output: storage 的 `scope_store` 与 `index` 模块、0003 迁移、`ontoforge scope plan|apply`、示例服务配置与文档。
</objective>
