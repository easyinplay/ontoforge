## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

> 来源说明见 03-01-PLAN.md 的 Phase Goal 节。

<objective>
把 03-08 写出的 edit log 锁成「不可变且足以重建 edit store」：tracer 先打通 append-only 触发器从迁移到两个后端的拒绝行为（UPDATE / DELETE / TRUNCATE / SQLite 替换式写入），再实现按 seq 重放重建 edit 表并逐列印证，确认重复提交各记一条，最后写 ADR-0026。

Purpose: STORE-03（不可变 edit log）、STORE-01（同一 conformance 双后端、idempotency 条目），实现 D-10 的「重放必须能重建 edit store」与 D-12。
Output: 0002 迁移中的触发器（两种方言）、`log::replay`、conformance 用例与 ADR-0026。
Scope 判定（plan-checker iteration 1）：本 plan 由拆分前的 edit log plan 拆出（见 03-08 objective），7 个文件（其中 `store.rs` / `sql_exit.rs` 只在 RESEARCH A4 回退时修改）、50k 估算。
</objective>
