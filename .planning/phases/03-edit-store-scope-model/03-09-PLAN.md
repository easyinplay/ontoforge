## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

> 来源说明见 03-01-PLAN.md 的 Phase Goal 节。

<objective>
「同源两处执行」的核心承诺：同一份行谓词编译成 SQL 与在 Rust 中求值结果一致。tracer 先打通「Pred → 代入主体属性 → printer AST → SQLite 执行 → 与 eval 比较」；再给 printer 加字符串匹配节点与两个方言的转义出口，用差分 proptest 与 Trino 固定语料锁住等价；最后实现多 role 合并 `TypeScope`，证明「A 的列 × B 的行」不泄露。

Purpose: SCOPE-04（差分覆盖）、SCOPE-03（多 role 合并）、SCOPE-05（无授权不构造 scope）、SCOPE-02（同属性多 role 授予的合并）。Phase 4 直接消费 `lower` 与 `TypeScope`。
Output: printer 的 `StringMatch`、auth 的 `scope::{lower, merge}`、差分 / Trino / 合并三组测试、PG 语料种子。
</objective>
