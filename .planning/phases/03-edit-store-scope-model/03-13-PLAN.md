## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

> 来源说明见 03-01-PLAN.md 的 Phase Goal 节。

<objective>
叠加语义的完整切片：调用方（Phase 5 的 Action、03-19 的 import）可以经同一个 `commit` 执行 unset、tombstone、release 与 M:N link 的 add / remove，并得到严格的版本与基数保证。tracer 先让四种对象操作与两种 link 操作都能端到端提交并入日志，再用独立编写的内存参考模型 proptest 锁住转移表（含日志重放），最后覆盖 1:1 基数与并发。

Purpose: STORE-07（叠加语义与 SC3 的参考模型 proptest）、STORE-05（edit store 写入时强制基数）、STORE-01（并发行为在两个后端一致）。
Output: 完整状态机、commit 的基数错误映射、参考模型与 proptest、conformance 用例。
</objective>
