## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

> 来源说明见 03-01-PLAN.md 的 Phase Goal 节。

pub enum RenameDecl { Property { type_name: String, from: String, to: String }, ObjectType { from: String, to: String } }
impl std::str::FromStr for RenameDecl { /* "Type.old=new" 或 "OldType=NewType" */ }

pub enum MigrationStep {
    Ddl(DdlStep),                                                                   // 新增类部分（建表、加列、索引）
    ArchiveColumn { type_name: String, property: String, column: String, archived: String, set_archived: String },
    RenameColumn { type_name: String, from: String, to: String },                   // 属性与 __set 列同时改名
    RenameTable { from_type: String, to_type: String, from: String, to: String },   // 含该表索引的重建
    ArchiveTable { type_name: String, table: String, archived: String },
    DropArchivedColumn { table: String, column: String },
    DropArchivedTable { table: String },
}
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct MigrationPlan { pub from_def_version: i64, pub renames: Vec<RenameDecl>, pub steps: Vec<MigrationStep>, pub hash: String }  // hash = FNV-1a 64 位十六进制，覆盖其余字段与新 ontology 的规范 JSON

pub async fn apply_migration(store: &EditStore, new: &Ontology, renames: &[RenameDecl], expected_hash: &str) -> Result<i64 /* 新 def_version */, MigrateError>;
pub fn plan_drop_archived(active: &ActiveDefinition) -> MigrationPlan;
pub async fn apply_drop_archived(store: &EditStore, expected_hash: &str) -> Result<i64, MigrateError>;
#[derive(Debug, thiserror::Error)] pub enum MigrateError { Definition(Vec<Diagnostic>), PlanChanged { expected: String, actual: String }, Store(StoreError) }
