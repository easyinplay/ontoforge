## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

> 来源说明见 03-01-PLAN.md 的 Phase Goal 节。

<objective>
reload 的第二个切片：部署方声明 `indexed: true` 或 oneToOne link 后，reload 自动建出对应索引，1:1 基数由数据库唯一索引强制；同时补齐 PG 标识符长度上限与物理名碰撞（ONT-V24）以及 link / 精度类变化的破坏性判定。

Purpose: STORE-02（索引是新增类变更、reload 自动执行；物理名问题在 DDL 前被拦下）、STORE-05（1:1 基数在 edit store 写入时强制的数据库侧；提交路径的错误映射在 03-11）。
Output: 索引模型与 DDL、名称上限与碰撞检测、diff 扩展与测试。
</objective>
