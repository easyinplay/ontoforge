## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 本机密钥文件 → dev 验证器 | 持有密钥文件即可签发任意主体的 dev 令牌 |
| 生产配置 → 验证器装配 | 部署方配置可能误带 `[auth.dev]` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-35 | Elevation of Privilege | dev 令牌在生产被接受 | critical | mitigate | dev 验证器只能经 `DevMode` 凭证构造，`from_config` 不构造；测试 `config_alone_never_enables_dev_tokens`；prohibition 已登记 |
