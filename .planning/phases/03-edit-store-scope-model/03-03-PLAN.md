## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

> 来源说明见 03-01-PLAN.md 的 Phase Goal 节。

<objective>
storage lane 的 tracer：部署方执行 `ontoforge reload` 后，edit store 按定义生成强类型 edit 表。先经 checkpoint 确认 edit 表的物理格式（set_mask 编码是 one-way 决定），再打通 SQLite 上「加载 → lint → 打开 store → 推导物理 schema → diff → DDL → 记录定义版本」整条路径与 `--dry-run`，最后补齐 PostgreSQL 后端（两个 schema、`COLLATE "C"`、`IF NOT EXISTS`）、两种方言的 DDL 快照、SQL 出口守卫与 ADR-0024。

Purpose: STORE-02（新增类变更自动 DDL、破坏性变更被拦下）、STORE-01（同一 store 代码在 PG 与 SQLite 上运行），实现 D-15、D-17。reload 的 `lock_timeout`、advisory 锁、Trino 可见探测与 `def_version` 栅栏在 03-16；索引与物理名长度 / 碰撞（ONT-V24）在 03-08；migrate 在 03-13。
Output: storage 的 store / naming / physical / ddl / diff / reload / sql_exit 模块、两套 0001 迁移、`ontoforge reload` 子命令、测试与 ADR-0024。
</objective>
