# Phase 10 Plan 01: Audit Timing Test Split

## Context

- `security::cap_counts_final_masked_row_and_version` 混用三段：16MiB cap 纯断言、
  `timeout(3s)` 轮询 `read_audit().health().pending` 墙钟等待、masked-row 纯断言。
  read_audit 的 `max_pending_age=1s` 背压在并行负载下偶发 `AuditUnavailable`。
- `cli_check_cardinality` 两个 E2E 用例用 300/500ms 紧预算 + 180ms/2s mock 延迟，
  全工作区并行负载下偶发超时（WINDOWS#18）。
- `ci.yml:59` 的 `--test-threads=1` 随 ea695ed（06-08 PG 审计）引入作为规避。

## 设计（经独立第二意见复核，方案一致且补强）

1. **纯断言拆分**：拆成两个独立测试，每个一个新 fixture + 一次 `execute_list`——
   `cap_counts_final_visible_row_and_version`（全列可见 → 16MiB 触发 cap）
   与 `cap_ignores_masked_large_source_value`（mask 在查询前配好，16MiB 不进入
   可见集）。无 audit 排序等待，完全确定性。删 pending 轮询与 lint allowance。
2. **SC2 期限测试**：`audit_pending_age_limit_fails_closed`——第二连接对同一
   edit.db 持 `BEGIN EXCLUSIVE` 锁使 sink 写确定性失败，bounded 15s 等
   `health().available` 转 false（明确失败文案），断言 `reserve` →
   `AuditUnavailable` 且 `of_read_audit` 落盘 0 行（durable 证据，
   pending==0 不算数）。
3. **E2E 宽余**：`cardinality_total_deadline_is_shared` timeout 500→5000ms、
   慢查延迟 2s→60s；`cardinality_budget_starts_after_precheck_and_pk`
   四 mock 延迟 180ms→1500ms、timeout 300→3000ms（语义不变：precheck+PK
   4.5s>3s 证明预算从 cardinality 轮起算，scan 1.5s<3s）；
   `incomplete_scan_is_not_clean` timeout 200→1000ms。
4. **ci.yml**：删除 `--test-threads=1`；`--ignored` 集成 job 的串行保留
   （共享外部服务，非本 phase 范围）。

## 关键事实（复核确认）

- flush 一次写全 batch，pending 只有 sink 写失败才驻留 >1s → 期限测试必须
  制造真实写失败（EXCLUSIVE 锁）。
- `open_with_read_audit` 注入缝存在但本方案不需要改 settings。
- `online.rs:858/900` 已有 `start_paused` 确定性覆盖 deadline 递减语义；
  E2E 只保留宽余协议验证。
- `read_audit` 用 `std::time::Instant`，tokio paused clock 不影响它。
