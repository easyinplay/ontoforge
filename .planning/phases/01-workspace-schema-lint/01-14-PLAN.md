# Plan 01-14：多文档 YAML 的编辑器 schema 关联（UAT gap G-1-2）

## Phase Goal

**As a** 编写 ontology 的开发者, **I want to** 用 YAML/JSON 编写 ontology 并通过 `ontoforge validate` / `ontoforge lint` 得到带源码定位的诊断, **so that** 定义错误在被存储、action、API 使用之前就被定位修正，且仓库在 Windows 本机 `cargo test` 全绿。

> 来源说明见 01-01-PLAN.md 的 Phase Goal 节。本 plan 只关闭 SCHEMA-07 的编辑器补全缺口（ROADMAP Phase 1 Success Criterion 5 的编辑器侧）。

<objective>
关闭 UAT gap G-1-2：yaml-language-server 只把 `# yaml-language-server: $schema=` modeline 应用到它所在的那个 YAML document（按 `---` 切分），aviation 示例只在文件第 1 行写了 modeline，所以第 2 个及之后的 document（包括 UAT 在文件末尾追加的 document）没有 schema，既无补全也无诊断。

按编排器锁定的四项决策修复（以下称「编排决策 1-4」）：
1. 新增项目级编辑器配置 `.zed/settings.json` 与 `.vscode/settings.json`，用 `yaml.schemas` 把 `./schemas/ontoforge-definition.schema.json` 关联到 `examples/ontologies/**/*.yaml`；manifest `ontology.yaml` 保留自己的 manifest modeline（modeline 优先于 settings，debug session 已实测）。
2. aviation 的 objects.yaml、links.yaml、actions.yaml 在每个 `---` 之后补定义 schema modeline（共 10 处）；validate、lint --deny-warnings、YAML/JSON IR 等价测试保持通过。
3. CONTRIBUTING.md 增加「编辑器接入」一节。
4. Rust 回归测试：编辑器配置可按 JSON 解析、引用的 schema 路径存在、glob 覆盖 aviation 示例文件；aviation 定义文件每个 YAML document 都以 modeline 开头。

Purpose: 示例 ontology 在编辑器里的每个 document 都按导出的 JSON Schema 补全和校验，SCHEMA-07「用于编辑器补全」的承诺在多文档文件上成立，并且由测试守住不再回退。
Output: 两份编辑器配置、aviation 三个定义文件的 10 行 modeline、`schema_export.rs` 中两个回归测试、CONTRIBUTING.md 新节。
</objective>
