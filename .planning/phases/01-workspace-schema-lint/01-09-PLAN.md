## Phase Goal

**As a** 编写 ontology 的开发者, **I want to** 用 YAML/JSON 编写 ontology 并通过 `ontoforge validate` / `ontoforge lint` 得到带源码定位的诊断, **so that** 定义错误在被存储、action、API 使用之前就被定位修正，且仓库在 Windows 本机 `cargo test` 全绿。

> 来源说明见 01-01-PLAN.md 的 Phase Goal 节。

<objective>
让开发者导出 ontology 定义格式的 JSON Schema，用于编辑器补全与 LLM 生成（SCHEMA-07）。schema 直接由 IR 类型的 `schemars` derive 生成（per D-02 的 kind 判别），产物入库并由漂移测试守住；示例 ontology 必须通过该 schema。

Purpose: 编辑器与 LLM 拿到的格式契约与 loader 实际接受的格式同源，不会漂移。
Output: `schema_export.rs`、`ontoforge schema export` 子命令、`schemas/` 下两份入库产物、两组测试、aviation 示例的编辑器 modeline。
</objective>
