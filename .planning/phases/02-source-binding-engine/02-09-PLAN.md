## Phase Goal

**As a** 部署 ontoforge 的开发者, **I want to** 把 object type 与 M:N link 绑定到已有 Trino 的物理表，并用 `ontoforge validate --online` 校验绑定, **so that** 应用与 agent 读到的是企业已有的数据，而 Windows 本机无需 Trino 即可用 SQLite 替身跑通全部测试。

> 来源说明见 02-01-PLAN.md 的 Phase Goal 节。

<objective>
把 `validate --online` 从「只能用 fixture 替身」扩展到部署方的真实环境：先用 tracer 打通「`--server-config` → profile 映射到 Trino → TrinoEngine（wiremock 模拟）→ 比对 → 诊断 / 退出码」，含不可用时的退出码 3、单 catalog 错误的隔离与配置错误定位，并经 wiremock 覆盖类型不兼容与表缺失；再交付 `--check-pk`（重复值查询排除 NULL）。按 eng review E1，原计划的「指向现成 SQLite 库文件的目录」模式与 `SqliteEngine` 的磁盘库入口整体删除。

Purpose: BIND-03（`validate --online` 对 Trino 校验、`--check-pk` 查重）、ENGINE-02（fail-closed 在 CLI 的体现：退出码 3）、ENGINE-01（CLI 发出 trace token 与 client tags）。
Output: `online.rs` 引擎选择与 `--check-pk`、`--server-config`、`pk_check.rs`、两组 CLI 测试与一组引擎测试。
</objective>
