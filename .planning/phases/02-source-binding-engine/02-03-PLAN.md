## Phase Goal

**As a** 部署 ontoforge 的开发者, **I want to** 把 object type 与 M:N link 绑定到已有 Trino 的物理表，并用 `ontoforge validate --online` 校验绑定, **so that** 应用与 agent 读到的是企业已有的数据，而 Windows 本机无需 Trino 即可用 SQLite 替身跑通全部测试。

> 来源说明见 02-01-PLAN.md 的 Phase Goal 节。

<objective>
交付绑定的定义层：新 kind `SourceBinding`（per D-01）、profile 目录规则与选定顺序（per D-05）、`backing` 与绑定的完备性校验（per D-02）、列映射默认同名（per D-03）、单表 / view 源（per D-04），以及 decimal `precision` / `scale`、manifest `defaultProfile` 的 IR 字段。先用 tracer 打通「一个 Flight 绑定文件 → IR → 校验 → `ontoforge validate`」，再接入 profile 选定与完备性，最后补齐结构性校验与 invalid 样例。

Purpose: BIND-01（绑定声明）与 BIND-02 的结构性部分（类型契约的 lint E 规则在 02-07）；为 02-05 的在线校验、02-07 的 lint、02-08 的类型兼容提供完整 IR。
Output: 绑定 IR 与 loader、`validate::check_profile`、`pipeline::check_with_profile`、`--profile`、aviation 双示例的 dev 绑定与最小 fixture、invalid 样例、重新导出的 JSON Schema。
</objective>

- `BindingTarget` 用外部标签枚举（YAML 写 `target: { objectType: Flight }` 或 `target: { linkType: flightCrew }`），不用 untagged（ADR-0003 spike：untagged 丢失错误路径）。

- profile 名不合法一律 ONT-V16（不论来自目录、manifest、`--profile` 还是环境变量）。
- `ONTOFORGE_PROFILE` 由 clap 的 `env` 特性读取（根 `Cargo.toml` 的 clap features 加 `"env"`，不改变 `Cargo.lock` 的包集合），库函数只收参数。
