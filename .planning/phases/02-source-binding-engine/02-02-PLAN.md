## Phase Goal

**As a** 部署 ontoforge 的开发者, **I want to** 把 object type 与 M:N link 绑定到已有 Trino 的物理表，并用 `ontoforge validate --online` 校验绑定, **so that** 应用与 agent 读到的是企业已有的数据，而 Windows 本机无需 Trino 即可用 SQLite 替身跑通全部测试。

> 来源说明见 02-01-PLAN.md 的 Phase Goal 节。

<objective>
建立 `ontoforge-engine` crate 的骨架与两条不变量：(1) 发给引擎的 SQL 只能来自类型化 printer（`PrintedSql`），(2) 值只经两个转义函数输出。先用一个 tracer 打通「printer 生成带字符串字面量的 SELECT → SQLite 替身执行 → 回读」，再补齐 Phase 2 需要的 AST 子集与方言差异、`PhysicalType` 解析和 SQLite DDL 文本生成，最后用 proptest 与源码级测试锁住不变量。

Purpose: ENGINE-03（注入防护由 proptest 与真实执行验证）、ENGINE-04（SQLite 替身支撑 Windows 本机 `cargo test`）；为 02-04（Trino client）、02-05（fixture 加载与在线校验）、02-09（`--check-pk`）提供 Engine 契约与 printer。
Output: 新 crate、workspace 依赖（本 phase 全部新依赖一次声明，后续 plan 不再改根 `Cargo.toml` 的依赖表）、三组测试。
</objective>
