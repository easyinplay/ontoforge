<interfaces>
`VersionTokenCodec` 继续使用现有 HS256 key material，但签名 message 从一个带固定 magic/version tag 的 `VersionClaims` canonical encoder 产生。claims 明确含 principal identity、规范化 attributes/effective TypeScope、logical type/pk、active definition version、source sample 和 edit state；map/set 按逻辑名称排序，数值与 JSON 使用既有 canonical value encoder，禁止 `format!("{:?}")`。

`PreparedReadSet` 为每个唯一 RowKey 保存事务前观察的 edit version（不存在行为 0）及可选 client token；`commit_action` 在 definition fence、command claim、稳定锁定完整 read/edit set 之后比较 observed version，再让 Action 对锁定状态调用 shared codec。token parse/signature/claims mismatch 对客户端统一映射 `ActionError::VersionConflict`，不暴露 key 或 claims 差异。

每个 task 走 ralph-loop completion contract；先记录 RED 的目标断言失败，再实现 GREEN，最后重构并重复 focused command。

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| query response -> client -> Action request | `_version` 经不可信客户端保存和回传，可能被篡改、截断或跨主体/范围重放 |
| Action pre-read -> storage transaction | 事务外 observed versions 与 source sample 可能在获取锁前过时 |
| locked state -> token verifier | verifier 必须使用 canonical logical claims，不能接收客户端 claims 或物理存储细节 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-08 | Tampering | `_version` token | high | mitigate | shared HS256 VersionTokenCodec、显式 format tag、canonical claims 和统一 signature verification |
| T-05-09 | Spoofing | token cross-principal/scope replay | high | mitigate | claims 绑定 principal、attributes、effective TypeScope、definition 与 logical row identity |
| T-05-10 | Tampering | no-token concurrent write | high | mitigate | 事务外 observed edit versions 在完整稳定行锁后逐项 CAS，冲突全事务 rollback |
| T-05-SC | Tampering | Cargo dependency resolution | high | mitigate | 不安装 package，只复用 workspace 内 query/action/storage 与锁定依赖；cargo 全带 `--locked` |
</threat_model>
