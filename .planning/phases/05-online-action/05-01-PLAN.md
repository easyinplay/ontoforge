## Phase Goal

**As a** 调用 ontology 的已认证客户端, **I want to** 只能通过受 scope 约束且可幂等重试的 Action 原子修改对象图, **so that** 每次写入都经过参数、授权和并发校验，可审计并可靠通知下游。

<objective>
建立 Phase 5 的 production-quality tracer：一个 edit-only、单 item、单 ModifyObject Action 从公共请求合同进入 storage-owned write transaction，在 SQLite 中原子写 edit、edit log、主体作用域 command receipt 与 outbox，并返回标准化摘要；随后把同一 schema 和成功合同扩展到真实 PostgreSQL。

Purpose: 最先验证 E1 的 hardest constraint，即 definition fence、command claim、稳定行锁和四类持久化写入能否共处于一个 storage-owned transaction；后续 scope、CAS、幂等竞态和 webhook worker 只扩展这条路径。
Output: Action API 骨架、两后端 migration、受控组合事务、SQLite tracer 与 PostgreSQL conformance。
</objective>
