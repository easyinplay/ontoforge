## 执行前最小修订 (2026-10-29)

源码核查发现 `QueryService::execute` 内部生成的审计 ID 未返回宿主。为满足原有 HTTP 与 durable audit 同 ID 验收，01-1 额外拥有 `crates/ontoforge-query/src/lib.rs`、`crates/ontoforge-query/tests/audit_pk.rs`，先读取这两个文件。

- 新增 `QueryService::execute_audited(request) -> QueryExecution`，`QueryExecution` 含 `request_id: Option<String>` 和 `result: Result<QueryPage, QueryError>`。ID 只复制现有 guard，不接受客户端指定 ID，不新增审计行。
- `execute` 保持原签名，委托 `execute_audited` 并返回 `result`。reserve 成功后的成功、业务错误与 finish 错误都返回同 guard ID；reserve 失败为 None。HTTP 对无 audit ID 的认证/早期错误使用服务端新生成 transport ID，不声称已有持久审计。取消沿用 guard Drop。
- 增加真实持久审计回归：成功、拒绝、reserve 失败、finish 失败的 ID/错误语义，保留现有 API 回归。先 RED 后 GREEN，不把脚手架编译失败作为 RED。
- 01-1 的 lib unit 测试放 `crates/ontoforge-server/tests/unit/tracer.test.rs`，由 lib 的 cfg(test)/path 模块加载；01-2 的 unit 测试放 `crates/ontoforge/tests/unit/serve.test.rs`，由 serve 的 cfg(test)/path 模块加载。指定 cargo --lib 命令不变。独立测试文件避免扩大 GSD Rust inline pathspec，使真实 RED test commit 可被现有 `*.test.*` gate 识别。首轮 workspace guard 将原 src 测试文件误判为生产写入，机械移动到 tests/unit，移除原 src 两个路径；不修改安全 guard/allow-list。tests/unit 不会被 Cargo 当作 tests 根下的独立 integration binary 自动发现。
- 保留完整 Cargo 日志，另用真实 cargo-nextest 原生 JUnit reporter 运行同一目标并提供新鲜报告给 `check tdd-red-evidence`；不编辑报告或全局 GSD。reporter 配置与记录归 `07-01-evidence/`。本机工具位置和版本见 findings。不得以零用例、陈旧报告或非目标失败授权 GREEN。

这项修订仅补足既有验收需要的兼容接口与证据，不变更已批准产品合同。后续 REST list/aggregate 接线前需复核各自审计关联入口，不能假定 pk 入口自动覆盖其他读取。

### 01-2 查询签名密钥装配补足

源码核查确认现有 ServerConfig 只有认证 key reference，缺少 Query TokenCodec 的可信持久 key。01-2 额外拥有 engine/config.rs、engine/tests/server_config.rs、examples/server/ontoforge-server.dev.toml、docs/api.md，并先读取实际文件。采用以下既有版本 token 合同所需的最小配置：

- 可选 `[query] signing_key_file`，配置解析保持旧命令兼容；`serve` 启动要求存在该可信引用。路径相对配置文件解析，沿既有 secret file 大小限制读取原始字节，至少 32 bytes。缺配置、读失败或长度不足均在监听前非零退出。
- 密钥独立于 auth.dev/OIDC，不复用认证密钥，不接受 HTTP 或 CLI 的明文值，不打印密钥，不在错误/Debug 中携带密钥。服务不对生产配置隐式创建或旋转 key；同一文件支持正常重启后验证既有 token。没有本次轮换需求，不新增 key id 前缀或多 key 框架，不改变现有 wire token。
- 通过临时文件和真实宿主测试同 key 跨启动验证、错误 key 拒绝、缺失/过短拒绝、认证 key 独立；核心行为先 RED 和证据判定再 GREEN。保留两个指定 serve_ 测试的实际执行；增加的配置测试也实际运行，不以编译通过代替验收。
- 示例仅包含指向 ignored target 目录的 key 文件路径，绝不提交 key。docs/api.md 记录 key 格式、路径和安全生成方式，只有说明与命令示例，不含真实凭据。07-12 后续 dev 初始化在持久 data dir 一次生成独立 key，正常重启保留，显式 reset 与 dev 数据共同重建。07-01 不提前实现完整 dev 生命周期。
