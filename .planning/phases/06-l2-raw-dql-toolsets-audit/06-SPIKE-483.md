# Phase 6 Spike: sqlparser 0.63.0 与 Trino 483 复验

**日期：** 2026-10-26  
**范围：** 根据 `.planning/research/spike-02-sqlparser-l2.md` 的描述重建代表性用例，复验 Display 与 Trino 483 的实际响应。此文档是 P2/P3 输入，不是 L2 安全验收通过记录。

## 结论

- 历史 104 个 ID 仅保留 Markdown 描述，**0 条原始 SQL 已恢复**。本次新构造等价用例 29 条（G 13、B 16），另有 75 个 ID 未覆盖。新构造用例不能替代原始 104 条的回归结论。
- `G11` 的 Display 将 `ROW(x BIGINT, y DOUBLE)` 改成 `ROW(x, BIGINT, y, DOUBLE)`；Trino 483 返回 `TYPE_MISMATCH`。round-trip AST 相等仍无法发现此语义损失，必须显式拒绝该类型形式。
- `G16` 的 Display 将 `OFFSET 10 LIMIT 5` 改成 `LIMIT 5 OFFSET 10`；Trino 483 返回 `SYNTAX_ERROR`。改成 `OFFSET 10 ROWS FETCH FIRST 5 ROWS ONLY` 后执行成功。
- `B53` 的嵌套注释在 GenericDialect 下被吞掉，Display 只有 `SELECT 1 FROM hive.s.t`，不含 `edit.s.secret`。仅此 Display 发往 Trino；它因当前容器无 `hive` catalog 返回 `CATALOG_NOT_FOUND`。未发送原文，不能从运行结果推出 ACL 安全性。

## 环境与方法

- `docker inspect --format '{{.State.Health.Status}} {{.Config.Image}}' ontoforge-trino-05-06` 返回 `healthy trinodb/trino:483`；`SELECT version()` 返回 `483`（query ID `20261026_042848_00016_jtvdc`）。地址 `http://127.0.0.1:58080/v1/statement`，请求携带 `X-Trino-User: ontoforge_spike`；轮询 `nextUri` 直到 `FINISHED` 或 `FAILED`。
- 在 `%TEMP%\ontoforge-spike483` 编译小型 Rust harness，依赖精确版本 `sqlparser = "=0.63.0"`、`serde_json = "1"`。执行 `cargo run --quiet`，使用 `GenericDialect` 逐条 `Parser::parse_sql`，记录语句数、`to_string()` Display 和 `parse(Display) == ast`。fixture 源码保留在该临时目录，本次没有写入仓库代码。
- harness **只探测解析/Display**，`expected` 是预期策略类别，**不是已实现的 AST 白名单判定**。仅静态挑选无副作用的 SELECT Display 发送到 Trino；含 DELETE/CALL/SET/越权表的拒绝样例没有发送。改写后的 G16/G48 是根据 Display 生成的候选只读 SQL，不能视为已有生产改写器。
- HTTP 实际共提交 14 次（含一次 `SELECT version()`）：10 次 `FINISHED`，4 次 `FAILED`。4 次失败分别是 G11 类型错误、G16 Display 语法错误、B53 缺失 catalog，以及首次构造无效的 G44 fixture；修正后的 G44 成功。G17、G16/G48 改写候选曾重测，因此请求数高于不同 SQL 的数量。所有拒绝策略类别仅在本地观察解析/Display，**没有执行生产 AST 白名单校验器**。
