# Phase 7.1 Research

## User Constraints (from CONTEXT.md)

以下逐字引用 `07.1-CONTEXT.md` 的 Locked decisions；该合同优先于下文实现建议。

- 新增`validate --online --check-cardinality`独立opt-in，要求`--online`；可与`--check-pk`组合，两个检查不替代。
- 不采用扩大`--check-pk`或默认online扫描方案：它们改变既有参数语义或默认成本。
- 仅遍历OneToOne的source-backed `link.to`对象，以其profile binding映射`foreign_key`与对象`primary_key`。不用link.backing判断，不要求from也是source。
- 现IR仅单列PK/FK。按非NULL FK分组，`COUNT(DISTINCT mapped_to_pk)>1`才是多个逻辑对象。相同PK与相同FK的重复物理行不算多个对象；NULL FK无连接；NULL/重复PK留给check-pk。
- 这是声明FK唯一性的source诊断，未评估被引用对象是否存在。诊断与文档明确此边界；不实现复合键、不做跨backend JOIN/referential integrity，不声称悬空引用合规。
- typed SQL AST/printer做最小CountDistinct扩展，保留PrintedSql私有构造与标识符quoting，不拼裸SQL。
- 独立warning码需核对现注册表/命名/文档后选择；warning默认exit0、deny-warnings exit1。有warning不显示“无违规”；schema/metadata预检失败不扫描、不声称已完成。
- 引擎失败、QueryOutput.truncated、超时、字节上限导致未完成，沿既有ONT-V19/exit3路径。保留已收集的诊断。复用QueryContext timeout/bytes并drain取消，不顺带重写PK检查。
- 最多20样本与第21 sentinel标识更多。LIMIT限制输出，不承诺限制扫描成本。OneToMany/editOnly不扫。
- 不改变L0/Action/service admission；report不阻塞业务读取。

## Architecture Patterns

### 1. 入口与数据流

```text
validate flags
  -> selected profile + offline schema checks
  -> describe bindings / compatibility
  -> opt-in? eligible OneToOne + usable source to-object binding
  -> typed COUNT(DISTINCT to_pk), grouped by non-NULL FK
  -> complete result? samples + more : ONT-V19
  -> cancellation drain
  -> existing Diagnostic renderer / exit-code mapping
```

[VERIFIED: crates/ontoforge/src/cli.rs:214-238; crates/ontoforge/src/online.rs:201-251] 现有字段原文为 `#[arg(long, requires = "online")] pub check_pk: bool`；`compare_all` 有两个生产调用点（Trino 与 SQLite）。建议增加同约束 `check_cardinality` 字段，并将参数传入这两处。全 crates 定向搜索未见手写 `ValidateArgs { ... }` 初始化；新增字段仍须由编译核实调用面。

### 2. 映射与适用对象

[VERIFIED: crates/ontoforge-schema/src/ir/link.rs:12-22,40-48,65-71; crates/ontoforge-schema/src/ir/binding.rs:125-151] 关键 IR 原文为 `OneToOne`、`OneToMany`、`ManyToMany`、`pub cardinality: Cardinality`、`pub to: LinkEnd`、`pub foreign_key: Option<PropertyName>`、`pub objects: BTreeMap<ObjectTypeName, SourceBinding>`、`pub fn column_for<'a>(&'a self, key: &'a str) -> &'a str`。推荐映射顺序：

1. 遍历 `ontology.link_types.values()`，只取 `OneToOne`。
2. 查 `link.to.object_type` 对应 ObjectType，要求该对象是 `Backing::Source`。
3. 从 `profile_bindings(profile).objects` 查 to-object binding；用通过 V17 / V19 预检的 object BindingKey 集合筛选。
4. 用 `binding.column_for(link.to.foreign_key)` 和 `binding.column_for(object.primary_key)` 分别映射物理 FK、PK，生成 `TableRef`。
5. finding 保留 logical link 名、to-object 的 BindingKey、物理表、样本及 more。映射到诊断时应明确 link、FK 与“不同对象数”，不能沿用 PK 文案。

[VERIFIED: crates/ontoforge-schema/src/validate/bindings.rs:335-350; crates/ontoforge-schema/src/validate/links.rs:107-191] `OneToOne | OneToMany` 不允许独立 SourceBinding；缺 FK 声明、属性不存在、类型不匹配已由 schema 拦截。故不能从 `bindings.links` 或 `link.backing` 判断本功能候选。仅 to 端 source、from 端 editOnly 仍必须检查；from 端是否存在实际对象不在本次扫描合同内。

### 3. typed CountDistinct 最小扩展

[VERIFIED: crates/ontoforge-engine/src/printer/ast.rs:32-44; crates/ontoforge-engine/src/printer/dialect.rs:109-130; crates/ontoforge-engine/src/printer/mod.rs:18-26] 当前 AST 原文为 `CountStar` 和 `Aggregate { func: AggregateFunc, arg: Box<Expr> }`；printer 对 `Expr::Column(name)` 调用 `quote_ident(name)`；`PrintedSql(String)` 字段私有，`fn new(sql: String) -> Self` 构造器也私有。

[CITED: 07.1-CONTEXT.md Locked decisions] 建议新增专用 `Expr::CountDistinct(Box<Expr>)`（拟定符号，非现有值），只增加 `dialect::expr` 分支，通过递归 `expr(arg, dialect)` 打印 `count(DISTINCT ...)`。避免给现有 `Aggregate` 加必填字段导致所有构造点改动，也不新增原始 SQL escape hatch。复用同一表达式构造于 projection、HAVING、ORDER BY。新增双方言快照并在真实 SQLite/Trino 执行验证。

设计 SQL（合同示例，尚未执行）：

```sql
SELECT "mapped_fk" AS "fk", count(DISTINCT "mapped_pk") AS "n"
FROM "catalog"."schema"."table"
WHERE "mapped_fk" IS NOT NULL
GROUP BY "mapped_fk"
HAVING count(DISTINCT "mapped_pk") > 1
ORDER BY count(DISTINCT "mapped_pk") DESC NULLS LAST, "mapped_fk" ASC NULLS LAST
LIMIT 21
```

[CITED: 07.1-CONTEXT.md] 同 PK 同 FK 的重复物理行不算多个对象；NULL FK 无连接；NULL PK 不参与 distinct 对象数，不在该检查额外报 PK 错误。只做声明的单列唯一性，不验证目标存在性。测试必须以这些行为验证 SQL，而不能只断言生成字符串含 DISTINCT。

### 4. 查询预算、截断与取消

[VERIFIED: crates/ontoforge-engine/src/lib.rs:23-31,53-82] 原文默认值为 `DEFAULT_QUERY_TIMEOUT_MS: u64 = 30_000`、`DEFAULT_MAX_ROWS: usize = 10_000`、`DEFAULT_MAX_BYTES: usize = 16 * 1024 * 1024`；`QueryContext` 包含 `timeout`、`max_rows`、`max_bytes`，`QueryOutput` 包含 `pub truncated: bool`。复用传入 timeout/bytes；样本查询需允许取到第 21 sentinel。若操作者配置更紧的 rows 上限，不静默扩大预算：查询不足且 engine 标记截断时按未完成处理。

[VERIFIED: crates/ontoforge-engine/src/pk_check.rs:119-168] 现 PK 模式设置 `sample_ctx.max_rows = MAX_DUPLICATE_SAMPLES + 1`、保留 20 样本，以是否取到第 21 个判断 more，但没有检查 `QueryOutput.truncated`。新模块应独立正确处理截断，不能顺带修改 PK 行为。成功取得 21 行且 `truncated == false` 是“超过20个冲突组”的有效样本结论；`truncated == true` 一律 ONT-V19/exit3，不能声称全量清洁或完整通过。

[VERIFIED: crates/ontoforge-engine/src/sqlite/mod.rs:380-470; crates/ontoforge-engine/src/trino/mod.rs:278-308; crates/ontoforge-engine/src/lib.rs:147-164] SQLite 使用 deadline + progress handler，Trino timeout/truncation/error 调用 `guard.cancel_now().await`；已有 `fn drain_cancellations(&self) -> impl Future<Output = Result<(), EngineError>> + Send`。CLI 在 async runtime 内结束检查后调用 drain，drain 失败追加 ONT-V19，保留已收集诊断；metadata 或检查错误分支同样必须到清理点。不要仅在成功分支 drain。

### 5. 诊断码与报告形态

[VERIFIED: crates/ontoforge-schema/src/diag.rs:218-222; crates/ontoforge-schema/src/lint/mod.rs:153-170; docs/source-binding.md:226-245] 注册事实：`pub const V18: &str = "ONT-V18"` 专属 PK，`pub const V19: &str = "ONT-V19"` 表示在线检查未完成；`KNOWN_RULE_IDS` 为 18 个离线规则，末项是 `"ONT-W11", "ONT-W17"`。文档原文：“诊断码一经发布不会复用或改义。”

建议新 online warning 使用 `ONT-W18`，在 `diag::codes` 增加常量并在 source-binding 文档单独注明它不是可配置离线 lint 规则；**不要**仅为接受这个 ID 而把它塞入 `KNOWN_RULE_IDS`，否则配置宣称可控制一个没有对应 LintRule 的检查。该编号是候选：本轮对 crates、source-binding 文档、ADR 的搜索无匹配；实施前再次冲突核查，并按实际选择同步 tests/docs。不复用 V18、W17。

[VERIFIED: crates/ontoforge-schema/src/diag.rs:8-12,52-62; crates/ontoforge/src/render.rs:126-133; crates/ontoforge/src/online.rs:75-88,268-301] `Severity` 原文为 `Error, Warning, Info`；诊断字段为 `code, severity, message, file, line, column, span, help`。warning 默认 exit0，`--deny-warnings` exit1；ONT-V19 exit3；已有 check_keys 保留 earlier findings 并区分 engine-wide 失败与单 binding 失败。新检查复用这些规则，但不要把结果写入 drift report / health / admission。

建议定位 to-object binding 的 FK 列映射（显式存在时），或绑定 source.table；message 包含 logical link、FK 和有界样本，help 明示未验证 referential integrity。样本使用现有 `display_value` 截断模式，不新增无界数据输出。CLI 摘要只说已比对多少绑定，不能把 warning 的 exit0 描述为“无违规”。

## Common Pitfalls

1. 用 count(*) 把同 PK 重复物理行算成不同对象；必须由 distinct 行为测试拦住。
2. 用 from backing 筛选，漏掉 source-to / editOnly-from；必须单独覆盖。
3. 对 OneToMany FK 唯一化；必须断言零 cardinality SQL。
4. 空数据、未检查、被预检跳过、截断混成同一空 findings；schema 错误保留失败，截断进入 V19，不能显示完整通过。
5. 只以 CLI exit0 断言没有冲突；warning 合同需要同时检查 JSON / human 文案。
6. 只运行 wiremock 或 ignored 测试提前 return 就宣称 Trino 通过；真实测试必须环境缺失失败并记录执行数量。
7. 修改默认 --online 或 --check-pk 查询数量；必须用请求记录断言 opt-in 边界。
8. 把 FK 字符串插值进 SQL；新增表达式必须经过 printer quoting，并保持 SQL 出口守卫。

这些是从锁定合同与上述源码模式推导的测试设计，不是本轮发现的新运行时失败。
