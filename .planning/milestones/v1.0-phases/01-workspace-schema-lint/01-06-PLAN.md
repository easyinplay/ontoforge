## Phase Goal

**As a** 编写 ontology 的开发者, **I want to** 用 YAML/JSON 编写 ontology 并通过 `ontoforge validate` / `ontoforge lint` 得到带源码定位的诊断, **so that** 定义错误在被存储、action、API 使用之前就被定位修正，且仓库在 Windows 本机 `cargo test` 全绿。

> 来源说明见 01-01-PLAN.md 的 Phase Goal 节。

<objective>
让开发者可以定义 action type：参数、有序 rules、结构化值来源与 submission criteria，并在引用错误与类型不兼容时得到 hard error（ONT-V09、V12）。aviation 示例补齐 3 个 action 的 YAML 与 JSON 版本。

Purpose: SCHEMA-05 的结构部分；Phase 3 的 action 执行、Phase 7 的 MCP 工具派生都只读这里的 IR。CEL 表达式检查在 01-07 与 01-12。
Output: `ir/action.rs`、`validate/actions.rs`、`basetype.rs` 的值类折叠与字面量校验、`tests/action_types.rs`、aviation actions、V03 / V09 / V12 样例与快照。
</objective>
