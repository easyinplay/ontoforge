## Phase Goal

**As a** 编写 ontology 的开发者, **I want to** 用 YAML/JSON 编写 ontology 并通过 `ontoforge validate` / `ontoforge lint` 得到带源码定位的诊断, **so that** 定义错误在被存储、action、API 使用之前就被定位修正，且仓库在 Windows 本机 `cargo test` 全绿。

推荐形状摘要（选项 recommended）：
- 文档：每个文档顶层 `kind: ObjectType | LinkType | ActionType`；YAML 可用 `---` 写多文档，JSON 可为单个对象或对象数组；`Interface` / `ValueType` / `SharedProperty` 预留，报 v1 不支持。manifest `ontology.yaml` 无 `kind`，字段 `apiName` / `displayName` / `description` / `include`。
- ObjectType：`apiName`、`displayName`、`description`、`aliases`、`hidden`、`primaryKey`、`titleKey`、`properties`（以属性 apiName 为 key 的 map，每项 `type`、`items`、`required`、`displayName`、`description`）。
- LinkType：`apiName`、`cardinality: oneToOne | oneToMany | manyToMany`、`from` / `to` 两端 `{ objectType, apiName, displayName, description, foreignKey }`；端 `apiName` 是「该端 objectType 上到达另一端的访问器」；`foreignKey` 只出现在 oneToOne / oneToMany 的 `to` 端，类型必须等于 `from` 端主键类型。
- ActionType：`parameters`（map，`type` 为 base type 或 `{ objectReference: <ObjectType> }`，另有 `items`、`required`、`default`、`description`）、`rules`（有序列表，`kind: createObject | modifyObject | deleteObject | addLink | removeLink`）、`submissionCriteria`（列表，`condition` 为 CEL 字符串，`failureMessage`）。
- 值来源（D-08）：单键结构化 map `{ param: x }` / `{ static: v }` / `{ currentUser: {} }` / `{ currentTime: {} }`。

撤销成本：本 plan 之后 01-03 至 01-12 全部按此形状实现，示例、JSON Schema 快照、invalid 样例与诊断快照都会固化该形状。
