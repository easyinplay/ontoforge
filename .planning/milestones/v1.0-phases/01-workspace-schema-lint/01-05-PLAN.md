## Phase Goal

**As a** 编写 ontology 的开发者, **I want to** 用 YAML/JSON 编写 ontology 并通过 `ontoforge validate` / `ontoforge lint` 得到带源码定位的诊断, **so that** 定义错误在被存储、action、API 使用之前就被定位修正，且仓库在 Windows 本机 `cargo test` 全绿。

> 来源说明见 01-01-PLAN.md 的 Phase Goal 节。

<objective>
让开发者可以定义 link type（1:1、1:N、M:N），并在引用错误、基数与外键不一致、访问器重名时得到带定位的 hard error。aviation 示例补齐 5 个 link type 的 YAML 与 JSON 版本。

Purpose: SCHEMA-04；link type 是 action 的 addLink / removeLink 与 Phase 4 searchAround 的基础，Phase 2 的基数约束（STORE-05）也读这里的 IR。
Output: `ir/link.rs`、`validate/links.rs`、`tests/link_types.rs`、aviation 与 aviation-json 的 links 文件、V08 / V09 / V11 样例与快照。
</objective>
