## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

> 来源说明见 03-01-PLAN.md 的 Phase Goal 节。

<objective>
写路径 tracer：一次提交在 edit 表中留下按属性 patch 的状态，同时在 edit log 与历史表中留下记录。先经 checkpoint 确认 edit log 的具体物理格式（D-10 / D-11 是 one-way：已写入的日志无法补出旧值，scenario / branch 将依赖它），再打通「Commit → 校验 → 行锁 → 新状态 → 日志 → 历史」，并建立同一套用例在 SQLite 与 PG 上运行的 conformance 框架。

Output: value / state / commit / log / history 模块、0002 迁移（两种方言，不含触发器）、conformance 框架。
Scope 判定（plan-checker iteration 1）：拆分前的 edit log plan（13 个文件、110k）按 orchestrator 决定拆为本 plan（日志格式 checkpoint + commit 写路径，12 个文件、70k）与 03-09（append-only 触发器 + 重放 + ADR-0026）。
</objective>
