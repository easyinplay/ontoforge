## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

> 来源说明见 03-01-PLAN.md 的 Phase Goal 节。

Purpose: STORE-02（运维可用的 reload 入口，D-15）、STORE-01（PG 与 SQLite 同一份 store 代码）。reload 的锁、栅栏与 Trino 可见探测在 03-18；PG 测试在 Linux CI 实跑在 03-20。

Scope 判定（plan-checker iteration 1）：本 plan 由拆分前的 reload plan 拆出（见 03-03 objective），11 个文件、65k 估算，均在预算内。
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09 | Information Disclosure | PG 连接串 / 系统表经 Trino 暴露 | medium | mitigate | URL 只经 `url_env` / `url_file` 且不进错误文本与 CLI 输出；系统表在 `schema_sys`，Trino 账号权限只授 `schema_edit`（ADR-0024、03-20 部署文档） |

| T-03-72 | Denial of Service | PG 上中断的 reload 留下半成品 | low | mitigate | PG DDL 一律 `IF NOT EXISTS`，定义版本只在 DDL 全部成功的同一事务内写入；`second_reload_on_pg_is_noop` 覆盖重跑 |
