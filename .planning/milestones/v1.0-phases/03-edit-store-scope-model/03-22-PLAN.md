## Phase Goal

**As a** 部署与运维 ontoforge 的开发者兼管理员, **I want to** 让加载的 ontology 自动生成并安全演进按类型强类型的 edit store、每次写入都追加不可变 edit log，并用 roles-as-code 配置用户 / 组 / 角色与 CEL 行谓词、用 OIDC JWT 或 dev token 认证, **so that** 后续的 scoped 读与 Action 写建立在同一份可审计的数据和同一套「SQL 编译与 Rust 求值结果一致」的授权规则之上。

> 来源说明见 03-01-PLAN.md 的 Phase Goal 节（沿用，未新编）。

<objective>
Gap closure 3（03-VERIFICATION.md gaps[2]，审查 WR-B07 与 WR-C05）：criteria 列覆盖（SCOPE-06 / ONT-V23）要在每条改变定义或 role 集合的路径上成立，并覆盖 criteria 的每一种读取方式（SC5）。

两个已证实的洞：

1. 破坏性定义变更只能经 `ontoforge migrate` 生效，而 `apply_migration_probed` 没有 role 输入，CLI 也不传。D-18 只在 reload 上执行：一个 role 引用了被归档或改类型的列，迁移后仍是「已 apply」。
2. `coverage::problem()` 第 88 行的 `path.segments.get(2)?` 让不带属性的 `objects.<param>` 读取直接返回 None，而 criteria 检查器接受这种写法（`expr/check.rs` 的 `object_problem` 在 property 为 None 时放行）。整对象读取（比较、`!= null`、传给宏）能揭示属性是否存在及其取值，正是 ONT-V23 要关掉的 dry-run 探测口。

Purpose: SCOPE-06「定义 reload 与角色变更时……否则报错不生效」覆盖 migrate 这条变更定义最多的路径（D-18 的语义延伸到 migrate）；D-01「criteria 列覆盖 lint 在 apply 前离线执行」不再有绕过的读取形状。
Output: storage `migrate.rs` 的 role 复核、CLI 接线、SQLite / PG / CLI 测试；`coverage.rs` 的整对象规则与测试；`docs/scope.md` 两段说明。

不做：`migrate --plan` 不预检 role（拒绝发生在 `--apply`，这是 gap 要求的安全性质；计划期预检属于体验改进，不在本 gap）；migrate 不创建 role 行谓词索引（reload 的 `missing_role_indexes` 是性能问题，不属于 SCOPE-06）；不改 reload 的实现。
</objective>
