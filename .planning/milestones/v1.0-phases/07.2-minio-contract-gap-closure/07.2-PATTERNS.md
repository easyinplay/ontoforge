这是已有边界模式，不是完整的新 owner 实现：旧脚本用固定名字和一个 started marker，不能证明每个容器/卷均由本次创建。D-03 已要求唯一 run owner label 和资源名；新 runner 需逐资源登记、失败中途仍可清理，并在删除前复核 owner。`ci/query-services.sh:90` 已有 Docker `--label` 语法，但其 catalog-dir label 只记录路径，不是所有权凭证。不得原样调用旧全局 cleanup 误删共享服务。

**退出码与清理失败传播**，`ci/server-services.sh:267–275`：

```bash
finish() {
  local status=$?
  trap - EXIT
  if [[ "$CURRENT_RUN_STARTED" -eq 1 ]]; then
    if [[ -s "$ENV_FILE" ]] && ! (check_artifacts); then status=1; fi
    if ! cleanup; then status=1; fi
  fi
  exit "$status"
}
```

同文件 281 行安装 `EXIT`、`INT`（130）、`TERM`（143）trap。250–264 行的 cleanup 会检测 Docker 不可用、删除后仍存在，并返回失败。可复用其错误传播结构；D-04 要求保留原失败 exit，原模板会在 scan/cleanup 失败时统一改成 1，需调整为仅在原操作成功时把 cleanup 失败转为失败。清理对象按 owner 核验，禁止复制固定容器集合。SIGKILL 不受 trap 保证；CI 另设 always cleanup，使用持久 owner 状态清理本 run 的 network、containers、volumes 和临时文件。
