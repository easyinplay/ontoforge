## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| 报告新鲜度伪装 | 只重算 fingerprint 或摘要就宣布旧阶段重新通过 | blocking | 每个被下游改动的阶段，用最终源码真实重跑对应测试套件，把原始输出写进新证据文件 |
| 计数外推 | 用一个 target 的成功数掩盖另一个 target 的零发现 | blocking | 逐 target 独立 discovery/execution 计数，任一为 0 即失败（07.2 已有 `test_one_empty_nonignored_target_cannot_be_hidden_by_another` 可复用） |
| 假绿矩阵 | 把 plan 通过当成 phase 通过、job success 当验收通过 | blocking | 每个 must-have 都要有具名测试或真实运行的原始输出，且 verifier 独立读取原始日志而非 SUMMARY 结论 |
| 资源越界 | 清理时删掉非本 owner 的容器/volume，或复用他人 Cargo 目录 | blocking | owner 标签 + 资源 ID 双重校验；同一台机器 Cargo/Docker 单一 owner，`CARGO_BUILD_JOBS=2` |
| 伪造工具调用 | 声称调用了 Warp/ralph-loop 等实际不可用的工具 | advisory | 写明「工具不可用 + 实际使用的替代闭环」，不伪称 |
| 第二意见诱导 | 把自己的方案塞进咨询问题再让对方背书 | advisory | 只给事实/需求/约束/代码，让对方独立出方案，再做对比 |
